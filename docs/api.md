# Courrier — API

Every HTTP route, generated by reading `apps/api/main.go` and each module's `router.go`.

## Conventions

- **Every application route lives under `/api`**, including the avatar file server — a
  single `router.Route("/api", ...)` block in `main.go`, with all six modules inside it.
  Only the health probes also answer at the root.
- Authenticated routes resolve a token from the `session` cookie first, then the
  `Authorization` header, then a deprecated `?token=` query parameter. The token is either
  a 30-day session token or a user's API token.
- Bodies are JSON, except the avatar upload and the send route, which also accept
  `multipart/form-data`. Ids in paths are integers unless noted; a non-numeric value
  returns 400.
- Errors are JSON from `tronc/httpjson`. `tronc/errors` maps `Invalid` to 400,
  `Unauthorized` to 401, `NotFound` to 404, `Conflict` to 409, `TooLarge` to 413, and
  `Internal` to 500.

## Service routes

| Method | Path | Auth | Response |
|---|---|---|---|
| GET | `/health` | no | `{"status":"ok"}` — liveness, touches no dependency |
| GET | `/ready` | no | `{"status":"ready"}`, or 503 `{"status":"not_ready"}` if the Postgres ping fails |
| GET | `/api/health` | no | Same handler as `/health` |
| GET | `/api/ready` | no | Same handler as `/ready` |
| GET | `/api/files/*` | no | Static file server rooted at `STORAGE_DIR`; this is where avatars are served |
| GET | `/*` | no | SPA catch-all, gzipped, mounted only when `CLIENT_DIR` contains an `index.html` |

## Auth

| Method | Path | Auth | Body | Response |
|---|---|---|---|---|
| GET | `/api/auth/config` | no | — | `{"sso_only": bool, "oidc_enabled": bool}` |
| POST | `/api/auth/logout` | no | — | `{"ok":true}`, deletes the session row and clears the cookie |
| GET | `/api/auth/resource-token` | yes | — | `{"token"}` — 5-minute HMAC token for inline images |
| GET | `/api/auth/oidc` | no | — | 302 to the provider |
| GET | `/api/auth/oidc/callback` | no | — | 302 to `OIDC_SUCCESS_URL` |
| POST | `/api/auth/sync-profile` | yes | — | Re-pulls name and avatar from the provider |

There is no register or login route: sign-in goes through Registre. The OIDC routes exist
only when `OIDC_ISSUER` is configured and discovery succeeded. Scripts, the CLI and mail
clients send an API token from Settings > API as `Authorization: Bearer <token>`.

The Android app signs in with porte's mobile flow: it opens
`/api/auth/oidc?flow=mobile&challenge=<S256 of a verifier>&state=<base64url>` in the system
browser, the callback redirects to `OIDC_MOBILE_REDIRECT` with `code` and `state`, and the
app trades them at `POST /api/auth/oidc/exchange` with `{"code","verifier"}` for
`{"user_id","token"}`. It then sends `Authorization: Bearer <token>` and no CSRF header.

## Users

All routes require authentication and are prefixed `/api/users`.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/` | — | `{"users":[User]}` |
| GET | `/me` | — | `{"user":User}` |
| GET | `/{id}` | — | `{"user":User}` |
| PATCH | `/me` | `name` | `{"user":User}` |
| POST | `/me/avatar` | `multipart/form-data` | `{"user":User}` |
| DELETE | `/me/avatar` | — | `{"user":User}` |
| GET | `/me/api-token` | — | `{"has_token", "name"?, "created_at"?}` |
| POST | `/me/api-token` | `{"name"}` | 201 `{"token","name","created_at"}` — the only time the token is returned |
| DELETE | `/me/api-token` | — | `{"deleted":true}` |

`User` is `{id, email, name, avatar_url, avatar_source, locale, created_at}`. `locale` is `fr`, `en`, `es` or `de`, taken from the Registre profile at each sign-in. The email and the password belong to Registre. `avatar_url` is a
path under `/api/files/`.

## Spaces

All routes require authentication and are prefixed `/api/spaces`. Space and member ids are
UUIDs.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/` | — | `{"spaces":[Space]}` — only spaces the caller belongs to |
| POST | `/` | `{"name","description"}` | 201 `Space` |
| GET | `/{spaceId}` | — | `Space` including a `members` array |
| PUT | `/{spaceId}` | `{"name","description"}`, both optional | `Space` |
| DELETE | `/{spaceId}` | — | `{"deleted":true}` |
| POST | `/{spaceId}/leave` | — | `{"left":true}` |
| GET | `/{spaceId}/members` | — | `{"members":[Member]}` |
| POST | `/{spaceId}/members` | `{"user_id","role"}` | 201 `{"id","space_id","user_id","role"}` |
| PUT | `/{spaceId}/members/{memberId}` | `{"role"}` | `{"id","role"}` |
| DELETE | `/{spaceId}/members/{memberId}` | — | `{"removed":true}` |

`Space` carries the caller's own `role` alongside `id`, `name`, `description`,
`created_at`, and `updated_at`. `Member` is `{id, user_id, email, name, role, joined_at}`.
Roles are `owner`, `admin`, and `member`.

## Accounts

Mail accounts — the IMAP/SMTP connections a user has configured. All routes require
authentication and are prefixed `/api/accounts`.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/` | — | `{"accounts":[Account]}`; accepts `?space_id=` |
| POST | `/` | `CreateAccount` | 201 `Account` |
| GET | `/{id}` | — | `Account` |
| PUT | `/{id}` | `UpdateAccount`, every field optional | `Account` |
| DELETE | `/{id}` | — | `{"deleted":true}` |

`CreateAccount` is `{name, email, imap_host, imap_port, imap_user, imap_password,
smtp_host, smtp_port, smtp_user, smtp_password, signature, is_default, space_id}`. IMAP
defaults to port 993 and SMTP to 587. `Account` returns everything **except the two
passwords** — they are stored AES-GCM encrypted and never leave the server.

## Mail

All routes require authentication and are scoped to one account.

### Sync

Paths are prefixed `/api/accounts/{accountId}/mail`.

| Method | Path | Rate limit | Response |
|---|---|---|---|
| POST | `/sync` | 5/min | `{"synced":true}` — lists and maps IMAP folders |
| POST | `/folders/{folderId}/sync` | 10/min | `{"synced":true}` — fetches messages for one folder |
| GET | `/folders` | — | `{"folders":[Folder]}` |
| POST | `/folders` | 10/min | `{"name"}` creates a top-level mailbox; 201 with the `Folder` |
| PATCH | `/folders/{folderId}` | 10/min | `{"name"}` renames a custom folder; the `Folder` |
| DELETE | `/folders/{folderId}?force=true` | 10/min | `{"deleted":true}` |

`Folder` is `{id, account_id, path, name, type, unread_count, total_count}`, with `type`
one of `inbox`, `sent`, `drafts`, `trash`, `junk`, `archive`, `custom`.

Folder writes go to the IMAP server first and the cache follows, so a refusal by the server
(412) leaves nothing behind. Only `custom` folders can be renamed or deleted; a system
folder answers 400. A name is 1 to 100 characters, without the server's hierarchy delimiter,
`/ \ * %`, control characters or a leading dot, and must not read as a system folder
(`Trash`, `Sent Items`, `Archive 2024`, ...), because the next sync would file it under
that type. A rename rewrites the cached paths of the folder's descendants, as IMAP renames
them with it. IMAP deletes the messages inside a mailbox with it, so a folder that holds
messages answers 409 unless `force=true` is set. Creation and rename answer 409 when the
name is taken.

### Reading

All paths below are prefixed `/api/accounts/{accountId}/mail`.

| Method | Path | Response |
|---|---|---|
| GET | `/folders/{folderType}/emails` | `{"emails":[Email], "total", "page", "limit"}` |
| GET | `/threads/{threadId}` | `{"emails":[Email]}` — every message in the conversation |
| GET | `/search` | `{"emails":[Email], "total", "page", "limit"}` |
| GET | `/emails/{emailId}` | A single `Email` with `attachments` |
| GET | `/contacts` | With `q`: `{"contacts":[{"name","email","count"}]}`. Without `q`: `{"contacts":[]}` (autocomplete contract, unchanged) |
| POST | `/contacts/backfill` | `{"scanned":N}`, or `{"running":true}` when a backfill is active on the account. Reads up to 1000 sent envelopes to fill contacts |
| GET | `/emails/{emailId}/attachments/{attachmentId}/download` | The file, fetched from IMAP on demand |

The folder listing takes `page` (default 1), `limit` (default 50, capped at 100), and
`unread=true`. Note the path segment is a **folder type**, not a folder id — `inbox`,
`sent`, and so on. Its rows are **collapsed conversations**, not individual messages: each
carries `message_count`, `unread_count`, and, when the conversation holds more than one
message, `email_ids`. Expand one with the thread route.

Search takes `q`, `page`, and `limit` (default 30, capped at 100), and runs against the
trigram indexes on subject, sender name, sender address, and body text. `contacts` takes
`q` and returns addresses seen in the account's mail with how often each appears. A blank
`q` on search or on the per-account `contacts` returns an empty result rather than an error.

`GET /api/mail/contacts` lists the addresses the user has written to, newest first, as
`{"contacts":[{"email","name","sent_count","last_sent_at"}],"total","page","limit"}`. It covers
every account the user can see, merging an address seen on several accounts into one row;
`account=<id>` restricts it to one account (404 if the user cannot see it, shared space
accounts of non-members included). `page` is capped at 10000 and `limit` at 100 (default 50).
It is rate limited to 60 per minute. Contacts are counted from the To and Cc of sent mail on
sync and on every send; `contacts/backfill` is idempotent and shares the per-account guard
of `mail/backfill`. Deleting an account or a space deletes its contacts.

`{threadId}` is percent-decoded before use, since a thread id is a Message-ID and can
contain characters that need escaping in a path.

### Triage

| Method | Path | Rate limit | Response |
|---|---|---|---|
| GET | `/api/mail/triage` | 60/min | `{"generated_at","total","counts":{"known","unknown_human","bulk"},"items":[TriageItem],"truncated","page","limit"}` |
| POST | `/api/accounts/{accountId}/mail/backfill` | 2/min | `{"classified":N,"scanned":N}`, or `{"running":true}` when a run is active |

`GET /api/mail/triage` covers the inbox of every account the user can see. Query:
`unread=true`, `class` (comma list of `known`, `unknown_human`, `bulk`, default all),
`since` (RFC3339 or `30m`, `2h`, `1d`, `1w`), `account` (one account id, 404 if it is not
the user's or a space account of which they are not a member), `page` (capped at 10000), `limit`
(default 50, capped at 100). `since` durations go up to 3650 units. `TriageItem` is `{account_id,
account, thread_id, email_id, subject, from_address, from_name, date, message_count,
unread_count, class, reason}`.

Class order: bulk signals first (`list-unsubscribe`, `list-id`, `precedence-bulk`,
`auto-submitted`, `noreply-sender`), then `known` (`in-sent-thread`: the thread holds a
message in a sent folder; `sent-to`: the sender is in contacts), else `unknown_human`
(`no-signal`). `counts` covers the whole set matching `unread`, `since` and `account`,
whatever `class` and `page` are; `total` and `items` follow `class`. Rows cached before
header classification existed fall back to the sender pattern.

The listing holds at most 5000 conversations, newest first. When more match, `truncated` is
`true` and `counts` and `total` describe only those 5000. `unread` and `since` are applied in
SQL before the cap; `class` cannot be, so narrow with `since` or `account` when `truncated`
is set. Every route here answers 404, never 403, for an account the caller cannot see.

`backfill` classifies cached inbox rows from the last 60 days that have no category, 50
headers per IMAP fetch with a pause between batches, then deep-syncs the sent folder into
contacts. It is idempotent and resumable (classified rows are skipped). A folder sync starts
it in the background when unclassified rows with an IMAP UID, in an inbox, from the last 60
days remain, at most one run per account, and not again for 15 minutes after a failed or
empty run.

### Inline images

`GET /api/accounts/{accountId}/mail/emails/{emailId}/cid/{cid}` is the only mail route
registered outside the `/mail` subtree, because it needs its own authentication path. A
browser loading `<img src="cid:...">` sends no `Authorization` header, so this route also
accepts `?token=` carrying a resource token from `GET /api/auth/resource-token`. It
verifies the HMAC and expiry first and falls back to the normal cookie/header path only if
that fails. The `{cid}` segment is percent-decoded.

### Writing

All paths below are prefixed `/api/accounts/{accountId}/mail`.

| Method | Path | Rate limit | Body | Response |
|---|---|---|---|---|
| PATCH | `/emails/{emailId}` | — | `{"is_read","is_starred"}`, both optional | The updated `Email` |
| POST | `/send` | 10/min | `SendRequest`, JSON or multipart | `{"sent":true}` |
| POST | `/drafts` | — | `SendRequest`, JSON or multipart | `{"id": <email id>}` |
| PUT | `/drafts/{emailId}` | — | `DraftRequest`, JSON or multipart | `{"id": <same id>}` |
| DELETE | `/drafts/{emailId}` | — | — | `{"deleted":true}` |
| POST | `/emails/bulk-action` | 30/min | `{"email_ids":[…], "action"}` | `{"ok":true}` |
| POST | `/emails/move` | 30/min | `{"email_ids":[…], "folder_id" or "folder_type"}` | `{"ok":true}` |

`SendRequest` is `{to, cc, bcc, subject, body, body_html, in_reply_to, references}`. As
`multipart/form-data`, `to`, `cc`, `bcc` and `references` are comma-separated strings and
files go in the repeated `attachments` field; the parse is capped at 25 MB and oversized
requests get 413. At least one of `to`, `cc` and `bcc` is required. Bcc recipients travel in
the SMTP envelope only: the delivered message has no `Bcc` header, while the copies in Sent
and Drafts, and the cached row, record it. `Email` therefore returns `bcc_addresses`
(`[]` when none). Sent mail is appended to the account's Sent folder over IMAP, drafts to
Drafts.

`DraftRequest` is a `SendRequest` plus `remove_attachments`, a list of attachment ids (a
comma-separated string in multipart). `PUT /drafts/{emailId}` replaces the recipients,
subject and bodies with the request's, keeps the row id and the Message-ID, and swaps the
Drafts copy on the server. Attachments already on the draft stay unless listed in
`remove_attachments`; uploaded files are added. A draft with attachments has to reach the
IMAP server, because the attachment bytes live in the server copy and are fetched from it
on download: when it cannot, the call answers 412 and a draft being updated is left
unchanged. Deleting a draft removes the server copy too. A draft that is not in the
account's Drafts folder answers 404.

`bulk-action` accepts `delete`, `archive`, `mark_read`, `mark_unread`, `star` and `unstar`.
An empty `email_ids` is a 400, and so is more than 200 ids; anything else in `action`
returns `unknown action`. `delete` moves to Trash; a message already in Trash is removed
from the server. `move` takes the destination as `folder_id`, or as `folder_type` for a
system folder; `custom` is not a valid type, since it names many folders. The move runs on
the IMAP server first (one `MOVE` per source folder), then the cached rows change folder
and take the uid the server assigned, keeping their ids. Messages already in the
destination are skipped.

### Connection test

`POST /api/mail/test-connection` (5/min) takes the full IMAP and SMTP host, port, user,
and password and answers `{"ok":true}`. It is registered outside `/accounts` because it
exists to validate credentials **before** an account is created, and it dials both servers
for real — so an error here is the honest report on whether an account will work.

## Templates and settings

Templates are reusable messages; all four routes require authentication and share a 30 per
minute rate limit. Settings exposes one boolean.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/templates` | — | `{"templates":[Template]}`; accepts `?space_id=` |
| POST | `/api/templates` | `{"name","subject","body_html","body_text","space_id"}` | 201 `Template` |
| PUT | `/api/templates/{templateId}` | Same fields | `Template` |
| DELETE | `/api/templates/{templateId}` | — | `{"deleted":true}` |
| GET | `/api/settings` | — | `{"settings":{"encryption_key_set": bool}}` |

`Template` is `{id, name, subject, body_html, body_text, created_at, updated_at}`. The
stored encryption key is never returned — only whether one is set.

## Push

All four routes require authentication. Bodies are generic: a notification names the sender
and the receiving address, never a subject or a body.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/push` | — | `{"enabled": bool, "native": bool, "web_push_key"?: string}` |
| POST | `/api/push/test` | — | 204; 409 when no channel is configured |
| POST | `/api/push/devices` | `{"kind":"fcm"\|"web","token","p256dh"?,"auth"?}` | 204; 409 when the server cannot send to that kind |
| DELETE | `/api/push/devices` | `{"token"}` | 204 |

`native` says FCM is on, and the Android app registers only while it is true.
`web_push_key` is the VAPID public key for `PushManager.subscribe`; it is absent while Web
Push is off. A web device's `token` is the subscription endpoint. Registering a token
another account owns moves it to the caller.

## Email shape

`Email` is `{id, account_id, folder_id, message_id, thread_id, subject, from_address,
from_name, to_addresses, cc_addresses, date, body_text, body_html, is_read, is_starred,
has_attachments, attachments, in_reply_to, references}`.

`to_addresses` and `cc_addresses` are arrays of `{name, email}`; `attachments` is an array
of `{id, filename, mime_type, size}`. `body_text`, `body_html`, `attachments`,
`in_reply_to`, and `references` are omitted when empty. `message_count`, `unread_count`,
and `email_ids` appear only on collapsed conversation rows from the folder listing.

## Registre notices

| Method | Path | Auth | Response |
|---|---|---|---|
| POST | `/api/registre/sync` | no | 202. A nudge that schedules an authenticated pull of Registre's snapshot |
| POST | `/api/registre/deletions` | signed security event | 202. Registre's `user.deleted` notice; the body is verified against Registre's keys, anything else is a 400 |

When Registre erases a person, Courrier deletes that person's account, personal mail accounts
with their cached folders, messages, contacts and rules, personal templates and memberships.
Mail accounts and templates attached to a space stay. The receiver also polls Registre, so the
push is optional; set `deletion_uri` on the Courrier client to receive it. `GET /version`
answers `{"version"}`, baked in at build time from `apps/client/package.json`.
